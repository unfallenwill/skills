# 项目全景综合任务提示词模板（阶段 0）

本模板用于派发**一个**一次性综合任务，在结构探测（probe_docs.py）完成后通读全部文本块，产出项目全景 `.pd-extraction/project-context.md`。全景是后续所有阶段的共享上下文：提取、规则编写、审核、溯源引用前先查全景，避免每次重新通读整份文档。派发时替换占位符：

- `{chunk_inventory}` — doc-map.json 中全部文档的 unit 清单（doc_id、unit_id、locator、chunk_file）
- `{doc_roles}` — 各 doc_id 的类型（protocol/dvp/dbdesign）与原始文件名

---

## 模板正文

你是临床试验数据管理专家。任务：通读本项目的全部源文档文本块，产出一份**项目全景**，供下游方案偏离（PD）规则提取与核实团队使用。下游团队不再通读原文，你的全景必须足以回答"这个项目是什么、三份文档分别讲了什么、去哪一块找什么"。

### 输入

文本块清单（逐块用 Read 阅读；文档大时优先覆盖结构性内容——目录、流程图、表格、汇总章节，叙述性段落可快读）：

```
{chunk_inventory}
```

文档角色：{doc_roles}

### 产出

写入 `.pd-extraction/project-context.md`（Markdown），包含且仅包含以下各节：

1. **试验概要**：适应症/人群、设计类型（如剂量递增、随机、盲法）、分组/剂量组、样本量、主要终点。信息散落在多处时给出主要来源定位。
2. **访视流程总览**：访视清单（名称/别名/目标时点/窗口/基准点），计划外访视与再筛选约定。以方案的评估时间表为准，注明其定位锚点。
3. **三源结构对照**：方案主要章节主题 ↔ DVP 规则族（按表单/主题分组，各组规则数与编号区间）↔ CRF/数据库设计的表单与数据集清单。逐行对应"同一主题在三份文档中分别位于何处"。
4. **项目词汇表**：项目特有缩写、代号、自定义术语（如药物代号、Part A/B、自设访视名）及含义；方案与 DVP/CRF 用词不一致处显式注明对应关系。
5. **关键数值与口径速查**：剂量、窗口天数、报告时限、阈值等高频被引数字及其来源定位（供下游直接引用，减少回查）。
6. **变量索引说明**：数据库设计文档的 sheet/数据集清单及其定位（指向 doc-map.json 的 sheets 概要——probe 已确定性提取各 sheet 表头，供 verify_variables.py 核实引用）；注明变量字典 variables.jsonl 将于阶段 1 由独立任务产出。无数据库设计文档时写明"未提供"。
7. **疑点与外部引用**：文中引用外部手册/其他文件导致无法展开的位置清单（定位 + 引用了什么），供下游判断是否需要向用户索取。

### 要求

- 全景中每条信息带来源定位锚点（`§章节` / `<Sheet>!R行` / `p.页码`），不臆造。
- 全文控制在 3000 字以内：全景是索引与速查，不是原文摘抄。
- 三份文档缺失某类时对应节写明"未提供"，不留空节。
- 语言跟随源文件。

### 返回

返回简短摘要：试验设计一句话概括、访视数、DVP 规则族数、表单/数据集数、疑点条数。
