# PD 类别体系（11 个固定类别）

本文件是阶段 1 提取与阶段 3 分类的唯一类别依据。类别字面量固定，逐字使用，不得增删、不得改写。

**使用方式：** 每个类别给出定义、典型子类、在三类源文档中的典型出没位置（模式提示）与提取检查清单。"出没位置"是寻找线索的启发式，**不是**章节名硬编码——实际章节名因项目而异，以 `doc-map.json` 探测到的结构为准。

---

## 1. 入选排除

**定义：** 受试者不满足任一入选标准、或命中任一排除标准，仍被入组/随机/继续参与试验。

**典型子类：** 入选标准不满足；排除标准命中；再筛选（rescreening）违规；随机化前资格确认缺失；入组后才发现的资格不符。

**典型出没位置（模式提示）：**
- 方案：研究人群/受试者选择相关章节，入排标准常以编号列表呈现；诊断与病情要求常嵌在"研究背景/目标人群"段落。
- DVP：eligibility / inclusion-exclusion 类核查规则。
- 数据库设计：资格确认类表单（记录每条标准 Y/N 的表单）。

**提取检查清单：**
- [ ] 每一条入选标准、每一条排除标准是否都有对应规则（逐条对照，不概括合并）？
- [ ] 标准中的客观阈值（年龄上下限、实验室指标界限）是否写入判定逻辑？
- [ ] 时间类标准（如"给药前 28 天内"）是否写清基准点？

## 2. 知情同意

**定义：** 知情同意过程不符合方案或伦理要求。

**典型子类：** 签署前已进行方案规定操作；使用错误/过期版本；签署日期异常（晚于首次方案操作）；再知情遗漏（方案修订后未重新签署）；见证人/法定代理人缺失（方案要求时）；签署页或记录缺失。

**典型出没位置（模式提示）：**
- 方案：伦理/知情同意相关章节；评估时间表的脚注常藏"须在知情同意后进行"类要求。
- DVP：ICF 日期与首次操作/检查日期的一致性核查。
- 数据库设计：ICF 表单（签署日期、版本号字段）。

**提取检查清单：**
- [ ] 首次同意与再知情是否分别成规则？
- [ ] "同意日期 ≤ 首次方案操作日期"这类比较是否写明比较的两个数据点？
- [ ] 版本号、见证人等条件性要求是否标注触发条件？

## 3. 访视

**定义：** 访视未按方案计划执行。

**典型子类：** 超窗访视；漏访视；失访；访视顺序错误；计划外访视未按规定记录。

**典型出没位置（模式提示）：**
- 方案：访视流程图 / 评估时间表（Schedule of Activities）及其脚注；访视窗口常以"±N 天"定义在时间表附近段落。
- DVP：访视日期 vs 窗口、访视间隔类核查。
- 数据库设计：访视日期表单。

**提取检查清单：**
- [ ] 每个有窗口的访视/评估时间点是否都有超窗规则？
- [ ] 窗口基准（首次给药日/随机日/上一访视日）是否写清？
- [ ] 漏访视与失访的判定（无法联系次数、随访努力要求）是否区分？

## 4. 给药

**定义：** 研究药物/治疗的给药不符合方案。

**典型子类：** 剂量错误；给药时间/间隔超窗；漏服/漏给；依从性低于阈值；给药途径或方式错误；剂量调整未按方案规则执行。

**典型出没位置（模式提示）：**
- 方案：给药方案/治疗相关章节；剂量调整规则常以表格呈现；依从性定义（如"实际服药量/应服量 ≥ 80%"）常在其附近。
- DVP：剂量、给药日期、依从性计算类核查。
- 数据库设计：给药记录表单。

**提取检查清单：**
- [ ] 依从性计算公式与阈值是否完整写入判定逻辑？
- [ ] 剂量调整的触发条件（毒性级别、实验室值）是否成规则？
- [ ] 漏服的量化定义（次数/连续天数）是否写明？

## 5. 样本采集

**定义：** 实验室检查/生物样本的采集、处理、储存、运输不符合方案。

**典型子类：** 采样超窗；漏采；样本处理/储存/运输条件不符；实验室使用错误（中心实验室 vs 本地）；方案要求的复查未执行。

**典型出没位置（模式提示）：**
- 方案：实验室评估相关章节；样本处理细节常引用独立的实验室手册（此时记录"引用外部手册"并在备注说明）；评估时间表中的采样行。
- DVP：采样日期窗口、采样缺失类核查。
- 数据库设计：实验室/采样表单。

**提取检查清单：**
- [ ] 每种样本类型的窗口与必采时间点是否覆盖？
- [ ] 处理时限、温度条件等数值是否写入判定逻辑？
- [ ] 漏采与超窗是否分别成规则？

## 6. 检查评估

**定义：** 方案规定的检查/评估项目未做、超窗或方法错误。

**典型子类：** 漏做检查；检查超窗；使用方案禁用的评估方法或设备；评估者资质不符；疗效评估时间点错误。

**典型出没位置（模式提示）：**
- 方案：评估时间表逐行（每一行评估项目都是候选规则）；疗效评估相关章节；各检查的操作要求段落。
- DVP：检查日期、检查缺失类核查。
- 数据库设计：各评估表单（生命体征、ECG、影像学、量表等）。

**提取检查清单：**
- [ ] 评估时间表中的每一行是否都核对过（必做 vs 条件性评估分别处理）？
- [ ] 条件性评估的触发条件是否写入判定逻辑？

## 7. 合并用药

**定义：** 合并用药/合并治疗违反方案的禁止或限制规定。

**典型子类：** 使用禁用药物；限制药物超许可条件使用；允许用药未记录；洗脱期不足；非药物合并治疗违规。

**典型出没位置（模式提示）：**
- 方案：合并用药/禁止与限制治疗相关章节；禁用清单常以列表或表格呈现。
- DVP：合并用药编码、用药起止日期与首次给药日期关系类核查。
- 数据库设计：合并用药表单。

**提取检查清单：**
- [ ] 禁用清单是否逐条/逐类转为规则（不概括为一条）？
- [ ] 洗脱期的时长与基准点是否写明？
- [ ] "允许但有条件"的药物，条件部分是否进入判定逻辑？

## 8. 不良事件

**定义：** 安全性事件的收集、评估、报告、随访不符合方案。

**典型子类：** AE 漏报/迟报；SAE 报告超时限；AE 随访缺失；妊娠事件未按方案流程处理；严重程度/相关性评估错误。

**典型出没位置（模式提示）：**
- 方案：安全性/不良事件相关章节（AE、SAE 定义与报告时限所在处）；收集起止时点（签署知情起/首次给药起）常在该章节开头。
- DVP：AE 日期逻辑、严重性与 SAE 标志一致性类核查。
- 数据库设计：AE 表单、SAE 表单。

**提取检查清单：**
- [ ] 报告时限的具体数字（如 24 小时）是否写入判定逻辑？
- [ ] AE 收集的起止时点是否写清？
- [ ] SAE 判定标准是否逐条成规则？

## 9. 随机盲法

**定义：** 随机化执行或盲态维护违反方案。

**典型子类：** 随机化程序错误（先给药后随机等顺序错误）；非计划揭盲；紧急揭盲未按流程；盲底管理违规；随机系统（IWRS/IRT）操作错误。

**典型出没位置（模式提示）：**
- 方案：随机化/盲法相关章节；揭盲的允许情形与紧急揭盲流程常在此处。
- DVP：随机号一致性、随机日期与给药日期顺序类核查。
- 数据库设计：随机化表单。

**提取检查清单：**
- [ ] 随机化与首次给药的时间顺序规则是否写明？
- [ ] 允许揭盲的情形是否逐条成规则？

## 10. 试验药品

**定义：** 试验用药品的储存、发放、回收、清点管理不符合方案。

**典型子类：** 储存温度/条件超标；药品清点/回收数量不符；超有效期使用；发放错误（发错人/发错药）；药品损毁或丢失未记录。

**典型出没位置（模式提示）：**
- 方案：药品管理相关章节；常引用药房手册（记录引用并在备注说明）。
- DVP：药品清点差异、有效期类核查。
- 数据库设计：药品管理/清点表单（如有）。

**提取检查清单：**
- [ ] 储存条件的具体数值（温度范围）是否写入判定逻辑？
- [ ] 温度超标后的处理流程要求是否成规则？
- [ ] 清点差异的处理阈值是否写明？

## 11. 程序

**定义：** 不属于以上十类的其他方案程序违规（兜底类别）。

**典型子类：** 方案规定的流程未遵循（数据修改流程、设备校准要求）；必需培训未完成即执行操作；必需文件/记录缺失；其他无法归类的偏离。

**典型出没位置（模式提示）：**
- 方案：散在于各章节的程序性要求（"须由经过培训的人员执行""设备须定期校准"等）。
- DVP：无法归入他类的核查规则。
- 数据库设计：各类管理性表单。

**提取检查清单：**
- [ ] 先尝试归入前十类，确实无归属才放本类；每条本类规则在备注说明为何不能归入他类。
- [ ] 程序性要求是否散在章节中被逐一遍历（依赖阶段 1 的按章节顺序通读通道）？

## 归类冲突处理

一条规则看似可入多类时，按以下判据取**一个**主类别（判据并列，按最贴合者取舍），不重复建规则：

1. 以偏离**对象**定类：对象是访视本身→访视；对象是访视中某检查→检查评估；对象是采样→样本采集。
2. 给药相关的偏离→给药，药品**管理**（储存/清点）相关的→试验药品。
3. 安全事件的处理流程→不良事件；安全相关的检查漏做→检查评估。

阶段 2 去重时若发现同一偏离被拆入两类，按上述规则归一，另一条记入"重复规则指向"。
