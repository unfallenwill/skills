# 文体规范：口播脚本（抖音/B站等）

为"读出来给人听"而写，判断标准与所有书面文体不同：**耳朵听得懂、一口气读得顺、留得住人**。改写前先默读原文，读着费劲的地方就是要改的地方。

## 高发问题

- **书面词汇听不懂**（"综上所述"、"其显著优势在于"）：全部换成说话用词——"所以说"、"它最大的好处是"。
- **长句一口气读不完**：按呼吸断句，一句话一个信息点。口播的句长上限远低于书面文。
- **精确数字听不进**（"提升了 32.7%"）：口语化为"提升了三成多"。需要精确数字建立信任的场合（如测评），保留精确值，但前后留白、放慢节奏。
- **同音歧义**（"全部"与"全不"、生僻缩略语）：换成无歧义的说法。
- **开头背景铺垫**：口播前 3 秒决定完播率，第一句必须是钩子——结论前置、悬念、反常识。铺垫全删。

## 改写倾向

- **听觉冗余合法**：适当重复关键信息（"记住，是 X，X 才行"）在书面文里是车轱辘话，在口播里是必要的——观众没法回看上一句。通用清单的"车轱辘话"标准在此放宽。
- 口语连接词是此文体的正常语言："那"、"然后"、"注意啊"、"你猜怎么着"。书面文里要删的这些词，口播里适量保留。
- 互动引导（"你们觉得呢"、"评论区聊聊"）：原文有则保留，原文没有不强加。
- 节奏标记：成品按信息点分行，换行即停顿位置，方便照稿录制。
- 平台差异：抖音节奏更快、句更短、钩子更前置；B站容忍更长的展开，但开头钩子同样必要。
- 红线不变：不得为了效果编造数据和亲历故事。
