# 文体规范：技术文章/文档

此文体的人味标准与其他文体相反：**克制优先**。技术读者反感的不是"不够活泼"，而是废话和模板腔。准确性永远压倒风格。

## 高发问题

- **"本文将介绍……"式开头**：删，直接说这是什么、解决什么问题。
- **代码块前后的空洞话**（"下面我们来看一段代码"、"以上代码展示了……"）：代码前一句话说明意图，代码后只解释非显然的部分。
- **每个方案都"各有优劣"**：技术写作的人味恰恰是敢下结论——什么场景选什么、为什么。原文有结论就摆明；原文确实没有结论，列入"待补充建议"，不代作者下结论。
- **官方腔文档**（把 README 写成产品说明书）：文档用祈使句直接给指令——"运行 X"，而不是"用户可以通过运行 X 来……"。
- **翻译腔修饰词**（"开箱即用的"、"健壮的"密集出现）：保留必要术语，删修饰性术语。

## 改写倾向

- 真实感来源（只能强化原文已有的，不能编造）：承认局限（"这个方案在 X 场景下不行"）、踩坑记录、性能数字、为什么不选另一个方案。
- 口语化尺度收紧：轻微即可——"注意这里有个坑"可以，再多就过了。
- 教程类的步骤序号和操作列表是功能性的，**不按通用清单的 bullet 滥用标准处理**。
- 严重程度校准：此文体词汇层容忍度更低（一个"赋能"就很刺眼），结构层容忍度更高（结构工整在文档中是优点，不是 AI 味）。
