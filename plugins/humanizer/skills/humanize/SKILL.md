# Humanize：去除 AI 味

## 首要认知

AI 味的根源是模型自身的默认审美：工整的排比、均匀的信息密度、面面俱到的立场、模板化的结构。因此**禁止凭"让文字更自然"的直觉改写**——那个直觉正是问题的来源，只会引入新的 AI 味。必须按 `references/ai-flavor-checklist.md` 的特征清单逐项诊断、逐项处理。

忠实原意是硬约束：原文的事实、观点、立场、数据，一个都不能增删或改变。

## 工作流

### 第 1 步：准备

1. 确定待处理文本：直接给出的文字、文件路径（用 Read 读取），或对话上文中的内容。
2. 确定强度档位：从参数或用户表述中识别，未指定时默认**标准**。
3. 判断文体并加载对应 reference：
   - 公众号/博客长文 → `references/genres/blog.md`
   - 技术文章/文档 → `references/genres/tech.md`
   - 营销/商业文案 → `references/genres/marketing.md`
   - 社交媒体短文 → `references/genres/social.md`
   - 抖音/B站等口播脚本 → `references/genres/script.md`

   用户未说明文体时从内容特征推断；无法判断则只用通用清单，不强行套文体。
4. 加载 `references/ai-flavor-checklist.md`。

### 第 2 步：诊断

对照清单，按四个层面标记原文命中的特征，记录位置、次数和严重程度：

| 层面 | 诊断对象 |
|------|----------|
| 词汇层 | AI 高频词、空洞大词、形容词堆砌 |
| 句式层 | 排比滥用、模板句式、句长均匀、翻译腔 |
| 结构层 | 总分总模板、bullet 滥用、段末小结、强行升华、信息密度均匀 |
| 气质层 | 无立场、过度 hedging、缺具体细节 |

先完成完整诊断再动笔——边诊断边改会遗漏，且容易只修浅层问题。

### 第 3 步：按强度改写

三档强度对应不同的编辑权限：

| 编辑动作 | 轻度 | 标准（默认） | 深度 |
|----------|------|------|------|
| 替换词汇、调整句式、删冗余词句 | ✅ | ✅ | ✅ |
| 删段末小结、合并车轱辘话、bullet 回归成句、改写开头结尾套话 | ❌ | ✅ | ✅ |
| 重组段落顺序、重新分配详略（重点展开、次要压缩） | ❌ | ❌ | ✅ |

**红线（任何档位都禁止）**：增删事实、观点、数据；改变立场和结论；虚构细节、经历、案例。

改写要点：

- 处理顺序从深到浅：先结构（若权限允许），再句式，最后词汇。先改词汇再动结构会白改。
- 原文中"若有具体案例/数据会更有说服力"的位置，**不代写**——在输出的"待补充建议"中提示用户补什么、为什么。
- 警惕过度矫正：强行加语气词、堆网络热梗、假装亲身经历，是比 AI 味更糟的"装出来的人味"。清单末尾"过度矫正警告"一节列有反例，改写后逐条自查。

### 第 4 步：忠实性自查

逐项核对改写前后：

1. **信息点**：事实、数据、例子有无增删。
2. **观点与立场**：结论和倾向是否原样保留。
3. **强调重点**：深度档调整详略后，原文强调的重心是否仍然突出。

发现偏差，立即回滚该处改动。

### 第 5 步：输出

按以下结构输出。原文来自文件时，成品写入新文件（原文件名加 `.humanized` 后缀）或按用户要求直接修改原文件，诊断报告和改动说明保留在对话中；直接给出的文本在对话中输出成品。

```
## 润色结果
<成品全文，或成品文件路径>

## 诊断报告
<按四层汇总：每层命中的特征、次数、严重程度（轻/中/重）；因档位限制未处理的问题单独标注，并提示用更高档位可处理>

## 改动说明
<按类别归纳改法，每类举 2-3 个「改写前 → 改写后」对照，说明理由>

## 待补充建议（如有）
<指出哪些位置由真实经历、数据、案例补充会显著提升，说明补什么最有效>

## 忠实性自查
<确认信息点、观点、立场无变化；深度档如做了详略取舍，说明取舍依据>
```

## 附加资源

- **`references/ai-flavor-checklist.md`** — 四层 AI 味特征详表：高频词表与处理方式、句式反模式、结构反模式、气质问题、过度矫正警告、严重程度标准。诊断与改写的依据，每次必须加载。
- **`references/genres/`** — 分文体补充规范（blog / tech / marketing / social / script），按第 1 步的判断加载对应文件。文体规范与通用清单冲突时，以文体规范为准。
